# Low-level hardware line tracing for EV3 · SPIKE Prime

LEGO **SPIKE Prime 허브**와 **EV3 브릭**으로 검정 라인을 따라가는 로봇의 Pybricks 실기 코드입니다. 그 코드를 **한 줄도 고치지 않고** PC에서 돌려 보는 시뮬레이터도 함께 있습니다.
Robotex 한국 레고 라인팔로잉 규정을 기준으로 합니다: 25cm 상자, 센서 4개 이하, 라인 20mm, 최소 곡률 반경 10cm, 직각과 교차로 있음.

- **방침**: 모터 파워는 100으로 고정하고, 감속 없이 조향만으로 달립니다. 예외는 긴 직선 끝 직각에서 거는 50ms 브레이크 하나입니다.
- **센서**: 컬러센서 3개를 23mm 간격 일렬로 바퀴축 앞 17cm에 답니다. SPIKE는 EV3 컬러센서를 `PUPDevice` raw 모드로 읽고, EV3는 `ColorSensor`로 읽습니다.
- **개발 방식**: 실기 블랙박스 로그로 시뮬을 실기에 맞추고, 시뮬에서 후보를 추린 뒤 실기에서 확인합니다.

## 하드웨어와 배선

| | SPIKE Prime | EV3 |
|---|---|---|
| 펌웨어 | Pybricks | Pybricks v4 (EV3 네이티브) |
| 컬러센서 | EV3 컬러센서 3개: C 좌 · A 가운데 · B 우 | S1 좌 · S2 가운데 · S3 우 |
| 구동 모터 | E 좌 · F 우(역방향) | A·B 좌(정방향) · C·D 우(역방향) |
| 회전 속도(요레이트) | 허브 IMU | 자이로 없음. 좌우 모터 각도 차로 계산 |

- **센서 배치**: 3개 일렬, 간격 23mm, 바퀴축 앞 170mm(렌즈 기준).
- **차체**: 바퀴 80mm, 윤거 205mm, 앞쪽에 볼 캐스터.
- **기어**: 20:12 기어를 다시 2배로 올려 직진 속도가 약 2.4m/s입니다.

## 사용 순서

1. **펌웨어와 파일 열기**: 허브에 Pybricks 펌웨어를 올리고 Pybricks Code에서 파일을 엽니다.
2. **빛값 재기**: `spike_value.py`(EV3는 `ev3_value.py`)를 실행하고 센서를 라인 위로 손으로 쓸면 `VALUE = [...]`가 출력됩니다. 이 줄을 주행 파일의 `VALUE` 줄에 붙여 넣습니다.
   - 주행 파일이 `RAW_MODE = True`면 `spike_value.py`도 `RAW_MODE = True`로 재야 합니다.
3. **주행**: 주행 파일을 실행하면, 센서 값이 들어오는 대로 화면이 꺼지고 바로 출발합니다.
   - SPIKE 화면: `S` 시작 · `P` 장치 연결 재시도 · `W`(주황 불) 센서 기다림 · `E`(빨간 불) 오류 · `B`(보라 불) 블랙박스 출력 중
   - EV3 화면: `START` · `PORT WAIT` · `SENSOR CHECK` · `WAIT` · `READY` · `ERROR` · `LOG...` → `DONE`
4. **자동 정지와 블랙박스**: 연습 중에는 `AUTO_STOP = True`입니다. 라인을 오래 잃으면(흰색 0.8초, 검정 0.3초, 회색 0.6초) 스스로 멈추고 마지막 2초 블랙박스를 출력합니다. **대회 때는 `AUTO_STOP = False`로 바꿉니다.**
   - 블랙박스를 출력하는 동안(보라 불 + `B`)은 아직 실행 중입니다. 불이 꺼진 뒤 누르면 새로 시작합니다.
   - 출력이 필요 없으면 `BB_PRINT = False`로 둡니다.
5. **분석**: 출력된 콘솔을 저장해 `python3 sim/bb_parse.py 로그.txt --events`로 해석합니다.

## 제어 로직 (E8 계열) 요약

- **오차**: 세 센서 진하기의 무게중심으로 라인 위치(mm)를 구합니다. 가운데만 라인을 볼 때는 가운데가 하얘진 정도로 크기를, 마지막으로 옆 센서가 본 쪽으로 방향을 정합니다.
- **게인 스케줄링**: 직선에서는 약하게(KP 0.088), 한쪽으로 오래 도는 곡선에서는 세게(KP2 0.433) 꺾습니다. 자이로 감쇠(KG)로 흔들림을 잡습니다.
- **라인을 놓치면**: 마지막으로 본 쪽으로 뱅킹합니다. 직진 중에 놓치면(직각) 제자리 회전하고, 2배 기어에서 너무 빨리 돌아 지나치지 않게 회전 속도 상한(300°/s)을 겁니다.
- **직각 예고**: 직진 중 가운데와 한쪽 옆이 함께 진한 검정(20% 미만, 3스텝 연속)이고 반대쪽이 흰색이면 그쪽으로 미리 꺾습니다. 0.3초 넘게 직진한 뒤라면 50ms 동안 양쪽 바퀴를 역회전해 세웁니다.
- **교차로**: 양옆이 함께 검정이면 직진합니다. E8R9는 가운데가 진한 검정이면 옆에 걸린 선(교차선)을 무시합니다.
- **출발·정지 안전장치**:
  - 센서가 0으로 읽히면 출발하지 않고 기다립니다. 1초마다 센서 모드를 바꿔 깨우고, 3초가 지나면 일반 반사 모드로 바꿔 달립니다.
  - 정지 버튼을 누르면 모터부터 세운 뒤 기록을 출력합니다.

## 시뮬레이터

`sim/`은 실기 Pybricks 코드를 그대로 실행하는 PC 시뮬레이터입니다. 모터 지연, 센서 발자국·노이즈·지연, 실측 루프 속도, 회전 미끄러짐을 반영합니다. 자세한 내용은 [`sim/README.md`](sim/README.md)에 있습니다.

```bash
# 지금 SPIKE 코드를 2배 기어 실기 모델(토크 한계 반영, geo2x)로 네 트랙에서 평가 (월드 32개)
python3.13 sim/tools/corner_eval.py '[["E8R8", {}]]' --src spike/spike_lf3_rule_e8r8_170.py \
  --profile spike_3s_geo2x --fwd 170 --weff 1.4,1.6 \
  --base '{"RAW_MODE": false, "VALUE": [34, 6, 22, 3, 21, 3], "AUTO_CAL": false}' \
  --tracks rightangle,main,hard,photo@1.3 --lost 450 --worlds 32
```

시뮬의 센서 목은 일반 반사 모드만 지원해서, `RAW_MODE False`와 시뮬 밝기에 맞춘 `VALUE`를 넣습니다.

## 실험으로 알게 된 것

시뮬 숫자는 후보를 추리는 용도라 실기와 다를 수 있습니다.

### 원(작은 루프)에서 갇히는 이유

원 반지름(약 12cm)이 센서 팔(17cm)보다 작아서 원을 계속 따라갈 수 없습니다. 몸은 원 안을 돌고 센서는 원 밖을 쓸다가, 두 번째 회전에서 교차점의 출구 선을 잡아야 빠져나갑니다. 그래서 팔이 원 중심에서 교차점까지 거리(약 17cm)만큼은 돼야 합니다.

실기 크기 원(시뮬 사진 트랙 1.3배)에서 원별 통과율과 다른 트랙 시간입니다. 2배 기어는 실기 회전 응답에 맞춘 토크 한계 모델(`spike_3s_geo2x`) 기준입니다.

| 구성 | 위 원 | 아래 원 | 직각 / main / hard |
|---|---|---|---|
| 1배 기어, 17cm, E8R8 | 97% | 94% | 4.19 / 2.95 / 2.22초 |
| 2배 기어, 17cm, E8R8 | 67% | 93% | 4.43 / 2.83 / 1.98초 |
| 2배 기어, 17cm, E8R9 | 50% | 77% | 4.23 / 2.81 / 1.99초 |
| 2배 기어, 15cm, E8R8 | 79% | 100% | 4.41 / 2.94 / 2.10초 |

- **2배 기어는 토크가 절반이라 회전이 빨라지지 않습니다.** 실기 블랙박스에서 제자리 회전을 시작하고 40ms 뒤 회전 속도가 1배 +106°/s, 2배 +144°/s로 비슷했습니다. 그래서 곡선(main·hard)에서만 빨라지고, 원과 직각에서는 손해입니다.
- **시뮬에서 기어비만 바꾸면 안 됩니다.** 기어만 2배로 한 모델은 회전이 두 배로 빨리 붙어서(+344°/s), 거기서는 E8R9가 위 원 82→90%로 좋아 보였습니다. 토크를 반영하니 반대였고, 실기에서도 효과가 없었습니다.
- 원 끝에서 같은 방향 회전을 막는 대책은 교차점까지 돌지 못해 오히려 나빴습니다(20~62%).
- 그림: [`sim/runs_geo/loop_arm_170_vs_150.png`](sim/runs_geo/loop_arm_170_vs_150.png) (토크 무시 모델로 그린 것이라 장면 설명용)

### 그 밖의 발견

- **센서 4개**: 4개 일렬로 그대로 옮기면 곡선은 비슷하지만 직각이 0.2~0.3초 느려졌습니다. 4번째 센서를 읽는 비용 자체(루프 3.5% 느려짐)는 결과에 거의 영향이 없었습니다. 그래서 3개를 유지합니다.
- **블랙박스와 정지 버튼**: PC가 연결돼 있으면 Pybricks의 `print`는 출력을 다 보낼 때까지 기다립니다. 또 정지 버튼은 `SystemExit`만 보내고 모터는 세우지 않습니다. 그래서 E8R8부터는 멈추면 모터를 먼저 세우고, 블랙박스를 2초 분량으로 줄였습니다.
- **루프 속도**: 초당 650~1,900회 범위에서 직각 지나침에 영향이 없었습니다. 지나침은 기계적인 회전 지연 때문입니다.
- **2배 기어 직각**: 제자리 회전이 900°/s까지 붙어 새 라인을 지나쳤습니다. 회전 속도 상한과 직각 브레이크로 해결했습니다.
