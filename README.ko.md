# 레고 라인트레이서 · SPIKE Prime & EV3

[English](README.md) | 한국어

LEGO **SPIKE Prime**과 **EV3**로 만든 3센서 라인트레이서입니다.
실기와 같은 코드 파일을 돌리는 시뮬레이터(PC·GPU·브라우저)로 다듬었습니다. 시뮬에서는 빛값만 시뮬 센서에 맞추고, 센서를 raw 모드 대신 반사광으로 읽게 합니다.

**▶ [브라우저에서 바로 실행](https://ijunsoo.github.io/Low_level_hardware_linetracing_for_ev3-spike/)** — 설치 없이 프로그램을 골라 달려 봅니다. 로봇 모양과 경기장도 바꿀 수 있어요.

| 항목 | 내용 |
|---|---|
| **대회** | Robotex 한국 레고 라인팔로잉: 25cm 상자, 센서 4개 이하, 라인 20mm, 최소 곡률 반경 10cm, 직각·교차로 |
| **주행 방침** | 파워 100 고정, 감속 없이 조향만 (예외: 긴 직선 끝 직각에서 50ms 브레이크) |
| **최종판** | SPIKE [`spike/spike_final.py`](spike/spike_final.py) · EV3 [`ev3/ev3_final.py`](ev3/ev3_final.py) |

## 1. 빠른 시작

> **최종판 하나만 쓰면 됩니다.** 바꿀 값은 맨 아래 한 줄에 모여 있어요.

### ① 빛값 재기

경기장 매트·조명에서 로봇을 바닥에 댄 채, 센서 3개가 라인을 완전히 지나가게 좌우로 여러 번 쓸어 줍니다.

| 로봇 | 실행할 파일 | 하는 일 |
|---|---|---|
| SPIKE | `spike/spike_value.py` (`RAW_MODE = True`) | 빨간 불 4초 동안 쓸기 → `VALUE = [...]` 출력 |
| EV3 | `ev3/ev3_value.py` (그대로) | 빨간 불 4초 동안 쓸기 → `VALUE = [...]` 출력 (RGB 반사광 %) |

### ② 붙여 넣기

출력된 `VALUE`를 최종판 맨 아래 줄의 `VALUE=[...]`에 넣습니다.

> EV3를 빨간 불로 달리려면 두 파일 모두 `RED_LIGHT = True`로 바꿉니다. 측정 코드가 주는 `VALUE_RED`·`VALUE0` 줄은 최종판 고급 설정에 넣습니다.

### ③ 출발

로봇을 라인 위에 놓고(가운데 센서는 라인, 좌우는 흰 바닥) 실행합니다. 센서가 준비되는 대로 출발합니다.

### ④ 기록 보기

- 연습할 때는 `AUTO_STOP=True`로 둡니다. 라인을 오래 잃으면 멈추고 마지막 2초 블랙박스를 출력합니다.
- 출력을 파일로 저장해 `python sim/bb_parse.py 로그.txt --events`로 해석합니다.
- **대회 때는 `AUTO_STOP=False`.**

## 2. 바꿀 값

SPIKE 최종판의 마지막 줄:

```python
line_trace(VALUE=[68, 12, 72, 12, 116, 12], GEAR=1.5, POWER=100, KP=0.057, KP2=0.269, KG=217, ST_BANK=60, ST_BANK_STR=100, RA_YAW=294, BRK_MS=50, AUTO_STOP=True, BB_PRINT=True)
```

| 값 | 뜻 | 이럴 때 바꾸기 |
|---|---|---|
| `VALUE` | 빛값 [흰, 검] × (좌, 우, 가운데) | 매트·조명·센서 높이가 바뀌면 다시 잼 |
| `GEAR` (SPIKE만) | 로봇 기어 (20:12 다음 단): 1.5 또는 2 | 기어를 바꾸면 최종판 주석에 있는 그 기어 줄로 통째로 바꾸기 (상수도 기어마다 다름) |
| `POWER` | 속도 | 기본 100 |
| `KP` / `KP2` | 직선 / 곡선 조향 세기 | 곡선 바깥으로 밀리면 `KP2` ↑ |
| `KG` | 흔들림 잡기 | 직선에서 좌우로 출렁이면 ↑ |
| `ST_BANK` | 곡선에서 라인을 놓쳤을 때 강제 회전 세기 | 원에서 휘두르면 ↓, 급커브에서 밀리면 ↑ (SPIKE 1.5배 60 · 2배 75 · EV3 85) |
| `ST_BANK_STR` | 직진하다 놓쳤을 때(직각) 회전 세기 | 100 = 제자리 회전 |
| `RA_YAW` | 직각에서 도는 빠르기 상한 (°/s) | 직각을 지나쳐 너무 돌면 ↓ |
| `BRK_MS` | 긴 직선 끝 직각 브레이크 (ms) | 0 = 끔 |
| `AUTO_STOP` | 자동 정지 | 연습 `True` / 대회 `False` |
| `BB_PRINT` | 멈출 때 블랙박스 출력 | `False`면 바로 끝남 |
| `YAW_ENC_K` (EV3만) | 모터 각도 → 회전 환산 | 기어 20:12면 245, 2배면 490 |

### 화면과 불빛

| 어디 | 표시 |
|---|---|
| **SPIKE 화면** | `S` 시작 · `P` 장치 재연결 · `W` 센서 기다림 · `E` 오류 · `B` 기록 출력 중 (꺼지면 다시 실행 가능) |
| **EV3 화면** | `START` · `PORT WAIT` · `SENSOR CHECK` · `WAIT` · `READY` · `ERROR` · `LOG...` → `DONE` |
| **주행 중 불빛** | 빨강 = 코너 예고 · 초록 = 라인 다시 찾음 · 노랑 = 강제 회전 |

## 3. 로봇과 배선

| | SPIKE Prime | EV3 |
|---|---|---|
| 펌웨어 | Pybricks | Pybricks v4 |
| 컬러센서 (EV3 컬러센서 3개) | C 좌 · A 가운데 · B 우 | S1 좌 · S2 가운데 · S3 우 |
| 센서 읽기 (최종판) | `PUPDevice` 모드 3: raw 반사광, 빨간 불 | `ColorSensor.reflection()`: RGB 반사광 (`RED_LIGHT = True`면 `LUMPDevice` 모드 3 빨간 불) |
| 구동 모터 | E 좌 · F 우 | A·B 좌 · C·D 우 |
| 회전 속도 | 허브 IMU | 좌우 모터 각도 차 (자이로 없음) |

- **센서 배치**: 일렬 23mm 간격, 바퀴축 앞 170mm
- **차체**: 바퀴 80mm, 윤거 205mm, 앞쪽 볼 캐스터
- **기어 (SPIKE)**: 20:12 다음 단을 1.5:1로 권장(직진 약 1.8m/s). 2배(약 2.4m/s)로 달릴 땐 최종판의 `GEAR=2` 줄을 씁니다.
- **EV3 센서 빛**: Pybricks 4.1부터 `ColorSensor.reflection()`은 빨강·초록·파랑 세 색으로 잰 반사광의 평균입니다. 그래서 센서 빛이 깜빡입니다. 실기에서 빨간 불 반사광보다 라인을 잘 따라가서, EV3 최종판은 이걸 기본으로 씁니다.

## 4. 주행 원리

| 상황 | 동작 |
|---|---|
| **평소** | 세 센서 진하기의 무게중심으로 라인 위치(mm)를 구하고, 오차 × 게인 + 자이로 감쇠로 조향합니다. 한쪽으로 오래 도는 곡선일수록 게인을 키웁니다(게인 스케줄링). |
| **라인을 놓치면** | 마지막으로 본 쪽으로 강제 회전합니다. 직진 중에 놓치면(직각) 제자리 회전하되 회전 속도 상한을 둡니다. |
| **직각 예고** | 직진 중 가운데와 한쪽 옆이 함께 진한 검정이면 미리 꺾습니다. 긴 직선 뒤면 50ms 브레이크. |
| **교차로** | 양옆이 함께 검정이면 직진합니다. |
| **출발 전** | 센서가 0이면 출발하지 않고 기다립니다. 모드를 바꿔 깨우고, 3초 뒤 반사광 %로 전환합니다. |
| **멈출 때** | 모터부터 세우고 블랙박스를 출력합니다. |

## 5. 시뮬레이터 · GPU · 강화학습

자세한 사용법은 [`sim/README.ko.md`](sim/README.ko.md)에 있습니다.

| 도구 | 하는 일 |
|---|---|
| **CPU 시뮬레이터** `sim/core.py` | 실기 Pybricks 코드 파일을 그대로 실행합니다(빛값·센서 모드만 시뮬에 맞춤). 모터 지연, 센서 발자국·노이즈·지연, 실측 루프 속도, 회전 미끄러짐을 반영합니다. |
| **GPU 시뮬레이터** `sim/rl/torchsim.py` | 같은 물리를 PyTorch로 16,384대 동시에 돌립니다(약 65만 결정/초). `sim/rl/sweep_gpu.py`로 규칙 기반 상수를 수천 설정씩 탐색합니다. |
| **강화학습** `sim/rl/ppo.py` | 규칙 기반 조향 위에 작은 신경망(잔차 정책)을 PPO로 학습합니다. `sim/rl/export_policy.py`가 정수 연산 Pybricks 코드로 내보냅니다(`spike/spike_lf3_rl.py`, `ev3/ev3_lf3_rl.py`). |

실기 블랙박스로 맞춘 기본 모델은 `spike_3s_geo2`(1배 기어)와 `spike_3s_geo2x`(2배 기어)입니다.

```bash
pip install -r requirements.txt                                                       # CPU 시뮬 (Python 3.9 이상)
python sim/run_sim.py spike/spike_lf3_rule.py --profile spike_3s_geo2 --track photo   # 한 번 달려 보기
python sim/regress.py                                                                 # 회귀 테스트 (15건)
```

```bash
pip install -r requirements-gpu.txt                    # PyTorch (CUDA·Apple GPU, 없으면 CPU)
cd sim
python -m rl.sweep_gpu --n 192 --no-slow               # GPU 상수 탐색
python -m rl.ppo --layout row3 --mode steer_only       # 강화학습
python -m rl.export_policy rl/runs/<이름>/policy.pt    # 실기 파일로 내보내기
```

## 6. 실험으로 알게 된 것

> 시뮬 숫자는 후보를 추리는 용도라 실기와 다를 수 있습니다. '원에서 갇히는 이유'와 '강제 회전 85 → 75'의 2배 기어 숫자는 2026-10-24 모형(시정수 ×3) 기준이라, 지금 모형(×2)에서는 조금 달라질 수 있습니다.

### 원(작은 루프)에서 갇히는 이유

원 반지름(약 12cm)이 센서 팔(17cm)보다 작아서 원을 계속 따라갈 수는 없습니다.

- 몸은 원 안을 돌고 센서는 원 밖을 쓸다가, **두 번째 회전에서 교차점의 출구 선을 잡아야** 빠져나갑니다.
- 그래서 팔이 원 중심에서 교차점까지 거리(약 17cm)만큼은 돼야 합니다.

| 실기 크기 원, 2배 기어 (같은 월드 48개) | 위 원 | 아래 원 |
|---|---|---|
| 센서 17cm, 강제 회전 85 (E8R8) | 67% | 90% |
| 센서 17cm, 강제 회전 75 (E8R10 = 최종판) | 79% | 77% |

- 센서를 15cm로 당기면(강제 회전 85) 위 79%·아래 100%였습니다(따로 돌린 32월드 실험).
- 원 끝에서 같은 방향 회전을 막는 대책은 교차점까지 돌지 못해 오히려 나빴습니다.
- 그림: [`sim/runs_geo/loop_arm_170_vs_150.png`](sim/runs_geo/loop_arm_170_vs_150.png), [`sim/runs_geo/loop_trap_170.png`](sim/runs_geo/loop_trap_170.png)

### 기어는 2배보다 1.5배 (시뮬, 2026-10-27)

SPIKE는 한쪽 바퀴를 모터 하나로 돌려서, 2배 기어에서는 토크가 모자랍니다. 2배는 최고 속도(2.38m/s)의 33~35%만 썼고, 90% 넘게 낸 시간은 0~2%였습니다.

| 경기장 6개 × 기본·무작위 9월드 (54판) | 완주 | 직각 |
|---|---|---|
| 2배 + 예전 상수 | 39/54 | 4.1초 |
| 1.5배 + 예전 상수 | 46/54 | 3.9초 |
| 1.5배 + 다시 맞춘 상수 (최종판 `GEAR=1.5`) | 49/54 | 3.8초 |

- 상수는 후보 100개를 연습 경기장 7개에서 거르고, 처음 보는 경기장 6개에서 검증해 골랐습니다(검증: 예전 상수 46/54 → 52/54).
- 1.5배 모형(`spike_3s_geo2_15x`)은 실측한 1배·2배 사이를 모터 물리식으로 이은 값입니다. 실기로 바꾸면 블랙박스로 다시 맞춰야 합니다.
- 더 센 LEGO 모터(Control+ L 등)로 바꾸는 효과는 −1~+3판뿐이었고, 펌웨어로 바꿀 수 있는 루프·센서 지연도 ±3판이었습니다.

### 그 밖의 발견

- **2배 기어로 바꿔도 제자리 회전이 두 배로 빨라지지는 않았습니다** (실기 회전 1번 기준).
  - 시뮬에서 기어비만 바꾸면 회전이 두 배 빨리 붙어서, 실기 회전에 맞춰 회전을 늦춘 `spike_3s_geo2x`로 평가합니다.
  - 10-24 모형(×3)에서는 곡선에서만 빨라지고 원·직각에서는 손해였습니다.
- **회전은 바퀴 미끄러짐이 좌우합니다.** 모터는 공개값(Pybricks 펌웨어 모델)으로 시뮬과 맞습니다. 하지만 바퀴가 매트에서 얼마나 미끄러지는지는 블랙박스로만 알 수 있습니다 → [물리 엔진 검토](docs/PHYSICS_ENGINE.ko.md)
- **강제 회전 85 → 75 (SPIKE)**: 사진 트랙 완주 9 → 13/48, 완만한 곡선 0.31초 빠름, 급커브 0.08초 느림. EV3(1배)는 75로 내리면 손해라 85를 씁니다.
- **센서 4개**: 4개 일렬로 옮기면 직각이 0.2~0.3초 느려졌습니다. 4번째 센서를 읽는 비용 자체(루프 3.5%)는 영향이 거의 없었습니다. → 3개 유지.
- **블랙박스와 정지 버튼**: PC가 연결돼 있으면 `print`는 다 보낼 때까지 기다리고, 정지 버튼은 모터를 세우지 않습니다. 그래서 멈추면 모터부터 세우고 기록은 2초 분량만 출력합니다.
- **루프 속도**: 초당 650~1,900회 범위에서 직각 지나침에 영향이 없었습니다. 지나침은 기계적인 회전 지연 때문입니다.
- **EV3는 RGB 반사광이 빨간 불보다 나았습니다.**
  - 빛값을 EV3에서 실측해 맞춰도(`[87, 17, 121, 21, 121, 19]`) 빨간 불 raw가 RGB보다 라인을 못 따라갔습니다(실기 2026-10-24).
  - 실기 블랙박스에서 센서가 라인 가장자리를 지날 때 4ms 뒤에도 값이 그대로인 비율이 RGB(EV3) 15%, 빨간 불(SPIKE) 35~38%였습니다. 빨간 불 모드 값이 더 늦게 갱신될 가능성이 있습니다(로봇이 달라 확정은 아님).
  - 왼쪽 센서도 빨간 빛에서만 28% 약했습니다(RGB는 10%).
  - → EV3 최종판은 RGB가 기본이고, `RED_LIGHT = True`로 빨간 불을 씁니다.

## 7. 파일 구성

## 8. 버전 기록

| 버전 | 바뀐 점 |
|---|---|
| E7 | 곡선 게인 스케줄링 |
| E8 | 라인을 놓친 뒤 강제 회전까지 기다리는 시간 24 → 2ms (턴 뒤 경직 해소) |
| E8R ~ R4 | 2배 기어용: 직진 중 놓치면 제자리 회전 + 회전 속도 상한, 직각 신호를 보면 미리 꺾기 |
| E8R5 ~ R7 | 직각 브레이크 (긴 직선 뒤에만, 50ms), 직각 신호 판정 엄격화, 출발 대기 |
| E8R8 | 멈춘 뒤 정리: 모터 먼저 정지, 블랙박스 2초, 출력 중 표시 |
| E8R10 | 곡선 강제 회전 85 → 75 |
| **최종판** | 바꿀 값을 맨 아래 한 줄로, 꺼진 실험 옵션 삭제 (시뮬에서 개발판과 결과 동일), EV3는 RGB 반사광 기본 (빨간 불은 `RED_LIGHT`) |
| **최종판 (10-27)** | SPIKE: 기어 1.5배 기준 상수 + `GEAR` 설정 (2배는 `GEAR=2` 줄). 블랙박스에 실제 기록 간격·보정 뒤 빛값 |
